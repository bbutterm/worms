# Worms Prototype

Прототип пошаговой артиллерийской игры. Локальный хотсит на одном устройстве,
без сети и без меню: открыл — сразу играешь.

Phaser 3 подключён через CDN, вся логика — ES-модули в `/src`.
**Встроенная физика Phaser, Box2D и Matter.js не используются вообще** —
блока `physics` нет в конфиге игры, весь интегратор и все коллизии написаны руками.

---

## Запуск

Нужен любой статический сервер (ES-модули не работают по `file://`):

```bash
npm run dev          # http://localhost:5173
# или
python3 -m http.server 5173
```

Отладочный параметр: `?biome=jungle|desert|snow|hell|forest|urban` фиксирует тему.

## Управление

| Действие                   | Тач / мышь                          | Клавиатура      |
|----------------------------|-------------------------------------|-----------------|
| Угол прицела               | кнопки ▲▼ справа                    | ↑/↓ или W/S     |
| Выстрел                    | держать **ОГОНЬ**, отпустить        | держать Space   |
| Выстрел (быстрый)          | свайп по бойцу: куда ведёшь — туда и летит, длина = сила | — |
| Ходьба                     | кнопки ◀ ▶                          | ←/→ или A/D     |
| Прыжок                     | кнопка ⤒                            | Enter           |
| Камера                     | тянуть за фон                       | —               |
| Вернуть камеру к бойцу     | кнопка ⌖                            | —               |
| Выбор оружия               | панель снизу                        | 1…4             |
| Новая карта (после победы) | тап                                 | R               |

Основная схема — как в оригинале: угол крутится кнопками, сила набирается
удержанием «Огонь», шкала над кнопкой показывает заряд, на максимуме выстрел
уходит сам. Палец при этом лежит в углу экрана и не закрывает поле — ради
этого схема и сделана. Слишком короткое нажатие (меньше 0.08 от шкалы)
выстрелом не считается, чтобы случайное касание не съело ход.

Свайп по бойцу оставлен как альтернатива: на мыши он быстрее, но на телефоне
кисть накрывает как раз то место, куда смотришь. Радиус захвата у него
маленький (34 px) — иначе он перехватывал бы протяжку камеры, начатую рядом
со своим бойцом.

Пока идёт набор силы (или тянется свайп) рисуется пунктирная подсказка —
первые 20 точек реальной траектории с учётом ветра и параметров конкретного
оружия, обрезанная по столкновению с землёй. Вне набора силы на луче прицела
висит прицел из оригинала, перекрашенный под команду.

### Камера

Карта втрое шире экрана, поэтому:

* в начале хода камера кадрирует бойца вместе с ближайшим противником,
  если оба влезают;
* дальше она идёт за бойцом **с мёртвой зоной** — трогается, только когда он
  подходит к краю ближе 340 px, иначе кадрирование хода тут же затиралось бы;
* карту можно тянуть пальцем за фон; через 2.5 с без касаний камера сама
  возвращается к бойцу, кнопка ⌖ возвращает сразу (в полёте — к снаряду);
* бойцы за краем экрана показываются столбиком указателей у края: цвет
  команды, здоровье и расстояние от того, кто ходит (32 px = 1 м).

Зума нет намеренно. Мир по высоте ровно с экран, поэтому при отдалении сверху
и снизу вылезает пустота, а вместе с миром масштабируются небо и весь
интерфейс — чтобы сделать это правильно, нужна отдельная камера под HUD и фон.
Для прототипа указателей и кадрирования достаточно.

## Ландшафт

Высота поверхности — сумма четырёх синусоид разной частоты плюс сглаженный
шум; результат умножается на оконную функцию, из-за чего края уходят под воду
и получается остров. Параметры октав, шума и пещер лежат в `biomes.js`.

Геометрия хранится **маской в offscreen canvas**: непрозрачный пиксель = твердь.
Взрыв стирает круг через `globalCompositeOperation = 'destination-out'`.

Поверх маски натянута текстура: тайл земли темы обрезается по маске через
`destination-in`, а верхний слой (трава / песок / снег) рисуется уже поверх
обрезки — вертикальными срезами по одному пикселю вдоль линии поверхности,
чтобы кромка повторяла рельеф и слегка торчала над землёй. Опалённый ободок
вокруг воронки кладётся через `source-atop`, поэтому ложится только на
существующую землю.

**Висящие в воздухе куски после взрыва не падают** — как в оригинале.

Две детали реализации:

* Рядом с маской ведётся зеркальный `Uint8Array` — читать `getImageData`
  на каждый пиксельный запрос физики было бы неподъёмно. Массив обновляется
  теми же операциями, что и канвас.
* Видимая текстура нарезана на вертикальные чанки по 640 px. После взрыва
  в GPU заливается только задетый кусок, а не все 3200×720 — на замерах это
  7.8 мс → 2.8 мс на кадр со взрывом.

## Физика

Снаряд интегрируется **4 подшагами на кадр**, и внутри каждого подшага идёт
попиксельная трассировка отрезка по маске — быстрый снаряд не проскочит сквозь
тонкую перемычку. Гравитация 800 px/s², ветер задаётся как горизонтальное
ускорение и разыгрывается заново в начале каждого хода в диапазоне −300…300.

Боец — прямоугольник 24×32 с попиксельной коллизией по нижней грани.
Перепад высот до 6 px за шаг проходится как склон, больше — стена.
Падение с высоты больше 100 px наносит урон. Здоровье 100, цифрой над головой.
В полёте боец интегрируется теми же подшагами, что и снаряд.

Взрыв стирает круг из маски, наносит урон линейно по расстоянию от эпицентра
и отбрасывает бойцов вектором от центра.

Отдельная тонкость про время. Физика идёт по дельте самого Phaser, зажатой
сверху: под нагрузкой лучше замедлиться, чем пропустить столкновение. А вот
таймер хода, набор силы и поворот прицела считаются по системным часам
(`performance.now`). Дельта Phaser для этого не годится — он её сглаживает и
на просадках отдаёт ровные 16.7 мс на кадр независимо от реально прошедшего
времени: на замере за 822 мс прошло 11 кадров, и все отчитались как 16.7 мс.
Тридцатисекундный ход растянулся бы на минуты.

## Ход

Две команды по два бойца ходят по очереди, внутри команды бойцы тоже
чередуются. Таймер хода 30 секунд; истёк — ход переходит. После выстрела ход
сразу переходит следующему (игра ждёт только, пока снаряд отработает и всё
успокоится). Победа — когда у команды не осталось живых.

## Как добавить оружие

Дописать объект в `src/weapons/index.js`:

```js
new Weapon({
  id: 'mortar', name: 'Мортира', icon: '◎', color: 0xffa0a0,
  spriteKey: 'proj_mortar',                     // необязательно
  projectile: { radius: 5, windScale: 0.5, gravityScale: 1.4 },
  explosion: { radius: 60, damageRadius: 95, damage: 60, knockback: 380 },
})
```

Кнопка в HUD и горячая клавиша появятся сами. Параметры снаряда:
`bounciness` (отскок), `fuse` (таймер самоподрыва), `digRadius`/`digTime`
(бурение земли), `drag` (сопротивление воздуха). Для нестандартного поведения
при попадании — переопределить `onDetonate`, как это сделано в `ClusterWeapon`.

## Как добавить биом

Добавить папку темы в `THEMES` в `tools/build_assets.py`, пересобрать ассеты
и дописать объект в `src/core/biomes.js`: цвет воды, запасные цвета и параметры
генерации (`octaves`, `noiseAmp`, `baseH`, `edge`, `caves`). Больше нигде
править ничего не нужно — в рипе доступно 29 тем, в игру включено 6.

## Спрайты

Графика — из Worms Armageddon. Исходные рипы лежат в `assets/raw/`
(архивы и распакованное дерево), а игровые ассеты из них **собираются**:

```bash
python3 tools/build_assets.py     # нужен pillow
```

Сборщик переводит палитровые PNG в RGBA (в рипах нет альфы — прозрачность
закодирована индексом 0 палитры), режет вертикальные ленты кадров в
спрайтшиты Phaser и выписывает размеры кадров в `src/core/sprite-meta.js`.
Подробности и таблица «что откуда» — в `assets/README.md`.

Любого файла может не быть — тогда рисуется цветной плейсхолдер и игра
остаётся играбельной.

## Деплой

**Vercel.** Статика, сборка не нужна:

```bash
npx vercel --prod
```

Framework preset — «Other», build command пустой, output directory — корень
репозитория. `vercel.json` задаёт кэш-заголовки и `frame-ancestors` для
Telegram; `.vercelignore` не пускает в деплой `assets/raw/` и `tools/`, так
что на прод едет около 2 МБ.

Заголовка `X-Frame-Options` там нет намеренно: значения `ALLOWALL` в
спецификации не существует, а часть браузеров трактует невалидное значение
как `DENY` — то есть он ломал бы ровно то, что должен разрешать. Встраивание
регулирует CSP. На нативные вебвью Telegram (телефон, десктоп-клиент) это не
влияет вовсе — там нет iframe, ограничение касается только Telegram Web.

**Telegram.** Через `@BotFather`: `/newapp` (или кнопка Web App у команды бота),
указать URL с Vercel. `src/platform/telegram.js` сам вызовет `ready()`,
`expand()` и заблокирует вертикальные свайпы, чтобы игра не сворачивалась
жестом. Игра ландшафтная — на телефоне её надо открывать горизонтально.

## Тесты

```bash
npm i -D playwright && npx playwright install chromium
npm test
```

`tests/smoke.mjs` поднимает статику, открывает игру в headless-браузере и
прогоняет настоящий игровой цикл: старт, выстрел каждым из четырёх видов
оружия через кнопку с проверкой воронки в земле, защиту от случайного тапа,
кнопки угла, протяжку камеры и возврат, свайп-выстрел, победу и рестарт.
Ничего не мокается. Если предустановленный Chromium не совпадает с ревизией,
которую ждёт playwright, путь к нему кладётся в `CHROMIUM_PATH`.

## Известные упрощения

* Звука нет.
* Ходьба через тач-кнопки, а не жестом — жест конфликтовал бы с протяжкой камеры.
* Зума камеры нет (см. раздел «Камера»).
* Ящиков с оружием и аптечек нет.
* Стартовые позиции разносятся в пределах окна 1700 px: при максимальной силе
  выстрела дальность около 1800 px, иначе противник оказался бы недосягаем.
